## ① 简历表述（推荐）

**FinCopilot —— 金融投研 Agent 工作台（个人项目）**　　　　　　　　Agent 开发　　2026.06 – 2026.09

**项目描述**：面向个人投研场景的金融研究 Copilot。用户给一句研究需求，系统自主完成**规划 → 多源取数 → 指标计算 → 图表成稿 → 独立风险终审**闭环，并要求所有结论性数字可回溯到具体接口与数据指纹。重点不在功能堆叠，而在 **Agent 运行时（状态机/事件）、记忆、幻觉抑制、上下文成本、评估与工具治理**这些决定"能否长期可信使用"的核心模块。

**技术栈**：Python（asyncio）、FastAPI + SSE、React 19 + TypeScript、MCP、SQLite + Parquet、tiktoken、Qdrant、Prometheus + Grafana + LangSmith、Docker + Railway、pytest（1818 条离线用例）

- 🆕 **Agent Loop 状态机**：把隐式轮次循环重构为 7 阶段 × 12 事件的显式 FSM，纯函数 reducer + 不可变快照（revision 单调递增），每次合法转移**先持久化再做副作用**，副作用经独立 effect runner 与状态机彻底解耦。恢复语义刻意定为 **at-least-once 而非假装 exactly-once**——只读调用用原 id 安全重试，结果不确定的写操作绝不静默重放而是重新进入确认，从机制上解决"崩溃即丢执行态"。

- 🆕 **事件驱动设计**：每次状态转移外发为一等事件且与 SSE 的 `phase` **一字不差**，监控侧落成可查询的 `trace_states`，使阶段时间线、阶段耗时与状态步数成为可直接计算的量。轮次轨迹每轮结束**实时落库**，进程崩溃不丢已发生轮次；实时写与批量写幂等共存，线上对话与评测共享同一观测面，指标由 7 项扩到 8 项。

- **记忆系统（三层长短期记忆）**：设计 L1 工作记忆 + L2 短期事件环 + LTM 长期记忆三层，并按**事实作用域而非存储位置**分层——对话内结论/引用按对话隔离，仅跨对话情节/语义记忆按 `user_id` 共享、绝不跨用户，从结构上避免"一份报告的问题污染所有对话"。LTM 以 SQLite 为唯一事实源，情节记忆零 LLM 成本结构化落库、语义记忆覆盖式 UPSERT 避免新旧口径矛盾，蒸馏以双保险触发绕开"无可靠会话结束时机"，向量检索三级降级使记忆链路不依赖向量服务可用性。

- **幻觉抑制**：建成贯穿取数→计算→成稿→复核的**溯源链**，结论数字强制标注 `{cite:cid}`、无来源数字自动注入 `[!无来源:n]`，并主动披露**数据时效**（按序列报最新期，避免"当期未发布"被读成"系统给了旧数据"）与**上游继承的默认值**（否则隐含筛选会被读成全局结论）。配套两条纪律：**校验即拒绝而非静默过滤**（静默丢弃会让模型误以为自己筛过了）、**取不到优于看似完整的错答案**，长文档摘要后回原文按页核数、定位不到就如实标注而不猜。

- **上下文压缩与成本优化**：以 80% 窗口 + 40 轮双阈值触发压缩，tiktoken 实算、切点强制落在 assistant 帧（否则孤儿 `tool_result` 触发 400，由真实 smoke 发现并加回归测试钉死）、失败可降级且绝不阻塞会话。将动态状态从 system prompt 迁至请求末尾后，实测**前缀缓存命中率 30% → 78%、全价 token 降约 67%**；结果按 token 预算裁剪，使 K 线类结果由 **~50K 压至 ~1K token**。

- **评估体系**：落成四维加权综合分（完成率 0.4 / 路径正确性 0.25 / 效率 0.15 / 安全性 0.2）+ **200 条 × 5 维度**用例集，红线门禁失败即返回非零退出码、可直接接 CI，并严守"只给规则真能检出的用例打红线"以免门禁形同虚设。轨迹逐轮落盘且**未执行的调用也记录**，使"高危调用被拦住"与"根本没尝试"可区分；新增动态编排维度专测技能注入与扇出，离线用例由 1546 增至 **1818 条**。

- **Tool 设计**：37 个工具（**21 常驻 + 16 按需**）以 `@tool`/`@param` 声明为唯一权威来源、覆盖测试兜底防漂移，并区分**能力（干什么）与策略（怎么干）**，使"是否用对工具"有唯一判定层。长尾数据源不做 70 个手写工具——参数 schema 运行时从上游 MCP 读取、新增端点零改码接入，同时把"上游默认值决定的筛选"与"调用方指定的"分开披露。

- **Skill 设计与确定性编排**：4 个场景 × 21 份方法论做渐进式披露，技能加载由**引擎按意图路由注入而非做成工具**，以"≥2 能力注流程 / 单能力注方法论"两道门槛避免无谓的上下文开销。🆕 进一步把编排决策从提示词下沉到引擎——实测提示词隐式触发扇出仅 **0/3**、改写为硬性指令也仅 **1/3**，改为引擎确定性判定后自然问法稳定扇出，且指令在成功后立即清除（否则子代理从 3 膨胀到 **12+**）。

- 🆕 **服务化交付**：补齐多阶段 `Dockerfile`（Node 构建前端 → `uv sync --locked` → **非 root 运行**）、`railway.toml` 与 `/v1/ready` 就绪检查（三个 SQLite store ping + 审计目录可写，失败 503），使"进程活着"与"依赖真的可用"可区分。状态路径统一外置到挂载卷，单 service 单 worker 即可部署跑通。

## ② 极简版（三条）

- **Agent 运行时**：把隐式轮次循环重构为 7 阶段 × 12 事件的显式 FSM（纯函数 reducer + 不可变快照、先持久化再做副作用），恢复语义为 at-least-once；每次状态转移外发为一等事件并与 SSE 阶段名一致，落成可查询的阶段时间线与实时指标，崩溃不丢已发生轮次。
- **可信与成本**：建成"取数→计算→成稿→复核"溯源链，结论数字强制 `{cite:cid}`、无来源数字自动标注；三层记忆按作用域隔离（对话内隔离、跨对话按用户共享）；压缩 + 缓存 + 裁剪三层治理使**前缀缓存命中率 30% → 78%、全价 token 降约 67%**。
- **工程化**：37 个工具以声明为唯一权威来源、长尾数据源 schema 运行时从 MCP 读取实现零改码扩展；技能渐进式披露且**编排决策从提示词下沉到引擎**（实测提示词隐式触发仅 0/3）；四维加权评估 + 红线门禁可接 CI，离线用例 1818 条，Docker + Railway 单 service 可部署。

### 🎯 面试防守

- **最能打的三条**：①前缀缓存 30%→78%（可复现实测，原理是 Provider 缓存顺序 `tools → system → messages`，任一环变化都会使其后全部失效）；②FSM 的 persist-before-emit + at-least-once（讲清"为什么不声称 exactly-once"即可）；③**扇出 0/3 的实测把决策从提示词下沉到引擎**——用数据推翻自己设计假设的典型例子。
- 主动讲**"为什么不做什么"**：`MEMORY.md` 文件视图永久不做（Web 形态不匹配）、`run_python` 不发布（同用户子进程不构成安全边界）、宏观子 Agent 明确不做（叙事型判断无法锚定可验证产出）。
- 时间区间按实际填写（仓库早期提交为 2026-09-10 起）。
