**FinCopilot —— 金融投研 Agent 工作台（个人项目）**　　　　　　**Agent 开发**　　　2026.06 – 2026.09

**项目描述**：面向个人投研场景的金融研究 Copilot。用户给一句研究需求，系统自主完成**规划 → 多源取数 → 指标计算 → 图表成稿 → 独立风险终审**的闭环，并强制所有结论性数字可回溯到具体接口与数据指纹。项目重点不在功能覆盖面，而在把 LLM 的不确定性收敛为**可治理、可量化、可回归**的工程系统：约 3.1 万行 Python（151 个源文件）、1546 条离线用例（不联网、零模型费用即可全量回归）、39 次提交。

**技术栈**：Python、FastAPI + SSE、MCP（JSON-RPC over Streamable HTTP）、React 19 + TypeScript、SQLite + Parquet、tiktoken、Qdrant + Embedding、Prometheus + Grafana + LangSmith、pytest

- **上下文压缩与成本优化**：长对话同时受「窗口溢出即断」与「成本随轮次线性上涨」两面夹击，落地**缓存 / 压缩 / 裁剪**三层治理。①**缓存**：定位到动态状态块拼接在 system prompt 上导致 Provider 前缀缓存每轮失效（缓存顺序 `tools → system → messages`，任一环变化使其后全部失效），将状态迁至请求末尾的临时 user 消息（不落盘、不进转录），实测**前缀缓存命中率 30~31% → 78%、全价（未命中）token 25344~25532 → 7366~8298，降约 67%**（同题同源双次运行复现）。②**压缩**：Auto-Compaction 以 80% 窗口 + 40 轮双阈值触发、**tiktoken `cl100k_base` 实算**（而非字符估算）、保留计划/结论/最近 2 轮，切点强制落在 assistant 帧（否则产生孤儿 `tool_result` 致 400，该缺陷由真实 smoke 发现并加回归测试钉死），超预算按 2→1→0 轮**逐级收紧**、摘要失败退化为计数式降级摘要，**绝不阻塞会话**。③**裁剪**：结果入上下文前按 token 实算并做列数自适应收缩（财报几十列时仅靠行数约束不住宽度），**K 线类结果 ~50K → ~1K token（-98%）**，完整数据留缓存供精读；另做提示词去重 **8 节 → 7 节，4272/3496 → 3490/2888 token（-17%）**。

- **幻觉抑制（可溯源优先于「看起来完整」）**：把「数字不可信」当作金融问答第一风险，建成贯穿**取数 → 计算 → 成稿 → 复核**的溯源链：每次取数登记一条 citation（接口/标的/参数/数据指纹/是否命中缓存），结论性数字强制标注 `{cite:cid}`；成稿阶段正则抽取「数字 + 单位」片段并校验所在段落是否含引用，**无来源数字自动注入 `[!无来源:n]`**——不可溯源即显式暴露，而非静默通过。同时强制披露三类容易掩盖事实的信息：**数据时效**（按序列而非整表报告最新数据期并注入当前日期锚点，避免「当期未发布」被读成「系统给了旧数据」）、**上游继承的默认值**（如估值快照默认只含两只个股，不披露就会被读成全市场结论）、**匹配与截断**（行业匹配、股票池截断均显式标注「可能不全」）。配套纪律直接写进契约：校验即拒绝而非静默过滤、取不到优于看似完整的错答案。

- **独立风险终审（多智能体的理由是隔离，不是并发）**：针对「作者看不见自己的错误」，成稿后**自动**启动独立上下文的终审子 Agent，在受限只读工具集内**重新取数核对**报告关键数字（`max_turns=6`、内容哈希闩锁防重复复核、高严重度问题阻断交付并触发修订）。真实运行中拦截过同一份报告内 **ROE 前后矛盾（17.72% vs 16.75%）**、**近一年收益率偏差（-12.43% vs -15.89%）**。同一机制推广为通用 `spawn_agent` 扇出：子代理一律只读、不取数、只回结论，把多份长文档与多条独立分析线的中间材料挡在主上下文之外。

- **工具与数据层（声明即契约 + 运行时 schema 发现）**：37 个工具（**21 常驻 + 16 按需**）不做手工维护清单，而是以 `@tool`/`@param` 声明为唯一权威来源（名称/类型/默认值取自函数签名，激活方式与能力归属来自声明），并配覆盖测试保证「每个注册工具都声明过能力，漏声明即 CI 失败」，从机制上消除声明与实现漂移、以及「工具有了却调不到」。长尾数据源不做 70 个手写工具——参数 schema 在运行时从上游 MCP `tools/list` 读取，**78 个端点零改码接入**；数据层为有序适配器降级链（同花顺 → akshare → …），降级对调用方静默但在引用中可见（`endpoint` 记录真实来源），并把「上游默认值决定的筛选」与「调用方指定的筛选」分开披露。

- **评测体系（把「改一处就悄悄退化」变成可拦截）**：四维加权综合分（**任务完成率 0.4 / 推理路径正确性 0.25 / 效率 0.15 / 安全性 0.2**）落到可自动执行、可出分、可接 CI 的体系，判定**看行为模式而非字面文本**（模型输出有方差）。关键设计是**轨迹单独落盘且记录「未执行的调用」**（权限拒绝、懒加载未激活、循环兜底拦截、超时）——只记录成功调用就无法区分「高危调用被拦住」与「根本没尝试」，安全维度会失去判据。用例集 **200 条 × 5 维度**（正常/信息缺失/工具失败/高风险/噪音），每个用例独立 cache/output/memory/audit 路径以免互相污染；**红线门禁用例失败即返回非零退出码**，可直接接 CI。配套 1546 条离线用例，以及端到端成本硬包络（一次完整研报 ≤ **240s / 600k token**，实测基线 **102s / 300,319 token、28 次工具调用**，覆盖「无界修订循环、缓存丢失」这类严重回归）；CI 分三层触发以免每次 push 都产生真实调用费用。

- **记忆与技能路由（按需注入，而非全量常驻）**：针对「压缩就丢上下文、追问反复重新取数」，设计 **L1 工作记忆 + L2 短期事件环 + LTM 长期记忆**分层，并**按作用域而非存储位置分层**（对话内结论/摘要/引用按对话隔离，跨对话情节与语义记忆按 `user_id` 共享、绝不跨用户），从结构上避免「一份报告的问题污染所有对话」。LTM 以 SQLite 为唯一事实源：情节记忆零 LLM 成本结构化落库，语义记忆 `(user_id, key)` **覆盖式 UPSERT**，保证用户新口径取代旧口径而不出现两条互相矛盾的记忆；向量召回**三级降级**（Qdrant → 本地余弦 → 键匹配），记忆链路不依赖向量服务可用性；蒸馏用**双保险触发**（后台扫描 + 开新对话补蒸馏），绕开 Web 形态「没有可靠会话结束时机」这一原始设计的死因。技能做成内容资产（**4 个投研场景 × 21 份方法论 + 报告模板**），且**不做成模型可调用的工具，而由引擎按意图路由注入**——注入落在会话状态块而非静态 system prompt（否则会把缓存边界推到对话最前端，抵消前缀缓存收益），并设两道门槛（≥2 能力命中注场景流程 / 单能力命中注方法论）：因此「茅台 ROE 为什么掉这么多」只拿到盈利方法论文档，而不会被塞进一整份权益研究流程。

## ① 简历表述（模块深挖版 · 面试展开用）

**FinCopilot —— 金融投研 Agent 工作台（个人项目）**　　　　　　　　Agent 开发　　2026.06 – 2026.09

**项目描述**：面向个人投研场景的金融研究 Copilot。用户给一句研究需求，系统自主完成**规划 → 多源取数 → 指标计算 → 图表成稿 → 独立风险终审**的闭环，并要求所有结论性数字可回溯到具体接口与数据指纹。项目重点不在功能堆叠，而在 **Agent 的记忆、幻觉抑制、上下文成本、评估与工具治理**这五个决定"能不能长期可信使用"的核心模块。

**技术栈**：Python、FastAPI + SSE、React 19 + TypeScript、MCP（JSON-RPC over Streamable HTTP）、SQLite（记忆/缓存/轨迹）+ Parquet、tiktoken、Qdrant + Embedding、Prometheus + Grafana + LangSmith、pytest（1546 条离线用例）

- **记忆系统（三层长短期记忆）**：针对长研究任务"压缩就丢上下文、追问反复重新取数"的问题，设计 **L1 工作记忆 + L2 短期事件环 + LTM 长期记忆**的分层架构，并**按事实的作用域而非存储位置分层**：对话内的结论/标的/摘要/引用**按对话隔离**，仅用户偏好与跨对话情节/语义记忆按 `user_id` 共享、绝不跨用户，从结构上避免"一份报告的问题污染所有对话"。LTM 用 SQLite 作唯一事实源，分**情节记忆**（做过什么：`decision`/`excerpt` 由懒蒸馏产出；"任务结果"的每轮结论自动升格为跨对话记忆属无约定写入，**默认关闭**）与**语义记忆**（知道什么：事实/概念/偏好，`(user_id, key)` **覆盖式** UPSERT，保证用户新口径取代旧口径而不会出现两条互相矛盾的记忆）；蒸馏用**双保险触发**（后台扫描器按对话闲置判定 + 用户开新对话时补蒸馏历史对话），绕开 Web 形态下"没有可靠会话结束时机"这一原始设计的死因。语义检索做**三级降级**——Qdrant KNN → 本地 BLOB 余弦 → 键匹配，记录本体永在 SQLite，向量服务不可用也不会让记忆链路断掉；情节与语义**共用同一次蒸馏调用**，因此语义记忆默认开启不增加 LLM 成本。

- **幻觉抑制（可溯源优先于看起来完整）**：把"数字不可信"当作金融问答的第一风险，建成**贯穿取数→计算→成稿→复核的溯源链**：每次取数登记一条 citation（接口、标的、参数、数据指纹、是否命中缓存），结论性数字强制标注 `{cite:cid}`，成稿阶段正则抽取"数字+单位"片段并校验所在段落是否含引用，**无来源数字自动注入 `[!无来源:n]`**；同时披露三类容易掩盖事实的信息——**数据时效**（按序列而非整表报告最新数据期、发布机构与节奏，并注入当前日期作为锚点，避免"当期未发布"被读成"系统给了旧数据"）、**上游继承的默认值**（如快照默认只含两只个股，若不披露就会被读成全市场结论）、**客户端匹配与截断**（行业匹配、股票池截断均显式标注"可能不全"）。配套三条纪律：**校验即拒绝而非静默过滤**（未知参数、枚举越界一律报错，因为静默丢弃会让模型以为自己筛过了）、**取不到优于看似完整的错答案**（提示词契约要求缺输入走 `ask_user`、超边界说明并给替代）、**长文档摘要后回原文核对数字**（map-reduce 归并后按锚文本落回页码、派子代理 `read_pdf` 精读补齐，定位不到就如实标注而非猜页码）。

- **上下文压缩与成本优化**：长对话命中"窗口溢出即断"与"成本随轮次线性上涨"两个矛盾，做了**压缩 + 缓存 + 裁剪**三层治理。
  ①**压缩**：以 80% 窗口为阈值触发 Auto-Compaction，用 **tiktoken `cl100k_base` 实算**（而非字符估算）、保留计划/结论/最近 2 轮原文，被裁区间压成带"此前取过 N 份数据、引用为 …"的摘要占位以保住可回溯性；针对"轮次多但每轮很小"的长期陪伴式对话**额外设 40 轮上限**（token 阈值管不住轮数）；切点强制落在 assistant 帧（否则产生孤儿 `tool_result`，OpenAI 兼容端点直接 400——该缺陷由真实 smoke 发现并加回归测试钉死）；超预算时按 2→1→0 轮**逐级收紧**，摘要失败则退化为"必须小于被替换内容"的计数式降级摘要，**绝不阻塞会话**；会话重载做**有界加载**（默认 200 轮，且仅当被跳过前缀确实已被摘要覆盖才截断，覆盖不足则回退全量，绝不做无声遗忘）。
  ②**缓存**：定位到状态块（计划/结论/召回/摘要/偏好）拼接在 system prompt 上导致缓存前缀每轮失效、整段历史按全价重算的问题，将动态状态迁至**请求末尾的临时 user 消息**（`[静态 system] + 历史 + [状态]`，不落盘、不进转录、不参与摘要），实测**前缀缓存命中率 30~31% → 78%、全价 token 降约 67%**（同题同源双次运行复现）。
  ③**裁剪**：结果进上下文前统一瘦身——预算**按 token 实算**并做列数自适应收缩（财报几十列时仅靠行数约束不住宽度），K 线类结果由 **~50K token 压到 ~1K**，完整数据留在缓存供精读；长表**按序列分组裁剪**，避免行数最多的序列占满预算导致其余序列一行都进不了模型。

- **评估体系**：针对"Agent 改一处就可能悄悄退化、且结果正确不等于过程合理"的问题，把四个维度落成**可自动执行、可出加权综合分、可接 CI** 的体系：**任务完成率 0.4 / 推理路径正确性 0.25 / 效率 0.15 / 安全性 0.2** 加权综合分，判定**看行为模式而非字面文本**（模型输出有方差）。关键设计是**轨迹单独落盘**：逐轮记录 `Thought/Action/Observation` 三元组，且**未执行的调用也记录**（权限拒绝、懒加载未激活、循环兜底拦截、超时）——只记录成功调用就无法区分"高危调用被拦住"与"根本没尝试"，安全维度会失去判据。用例集 **200 条 × 5 维度**（正常/信息缺失/工具失败/高风险/噪音），每个用例独立 cache/output/memory/audit 路径以免互相污染；**红线门禁用例失败即返回非零退出码**可直接接 CI，并严守"只给规则真正能检出的用例打红线"的纪律（无法判定的标注 `judge: todo` 而不打红线，否则门禁形同虚设或误报）。配套 1546 条离线用例（不联网、零模型费用），CI 分三层触发以免每次 push 都产生真实调用费用。

- **Tool 设计（声明即契约 + 两级注册）**：37 个工具（**21 常驻 + 16 按需**）不做成一份手工维护的清单，而是**由 `@tool`/`@param` 声明作为唯一权威来源**——名称/类型/默认值取自函数签名、常驻或按需来自声明、能力归属来自 `capability`，并配覆盖测试保证"每个注册工具都声明过能力，漏声明即 CI 失败"，从机制上消除"声明与实现漂移"和"工具有了却调不到"。针对**能力（干什么）与策略（怎么干）**分层：换能力才可能是用错工具，同能力的参数差异（`detail`、`with_text`、`method`）只是策略，使"是否用对工具"有唯一判定层。长尾数据源**不做 70 个手写工具**——参数 schema 在运行时从上游 MCP `tools/list` 读取、上游新增端点零改码接入，同时把"上游默认值决定的筛选"与"调用方指定的"分开披露。取数复用落成一条有名字的策略（同参数自动命中缓存 → `detail="full"` 取更多行列仍走缓存 → 计算/绘图用 `cids` 复用已取数据），避免重复取数与重复计费。

- **Skill 设计（渐进式披露 + 路由注入）**：把投研方法论做成**内容资产**而非提示词堆砌：4 个场景各含 `SKILL.md`（流程/边界/输出契约）+ `references/`（21 份方法论，一个分析维度一份）+ `assets/`（报告模板），文件清单由**目录扫描**得出而非在 frontmatter 重复声明（杜绝"声明了却不存在"）。关键决策是**技能加载不做成模型可调用的工具，而是引擎的路由动作**——模型不该管理自己提示词里放什么，且"该不该加载"取决于意图、而意图在模型发出任何调用之前就已在文本中可判定，做成工具只会让每份方法论多付一次往返。路由采用**两道不同门槛**实现按需注入：场景流程需 ≥2 个研究能力命中（流程描述整篇研究编排，对单点提问是无用开销），方法论文档单个能力命中即注入（它回答"这个指标该怎么读"，单点提问正需要）；因此"茅台 ROE 为什么掉这么多"只拿到盈利方法论文档，而不会被塞进一份完整的权益研究流程。注入按目标幂等去重、且**落在会话状态块而非静态 system prompt**（否则会把缓存边界推到对话最前端，抵消前缀缓存收益），每次注入发射事件使"模型为什么知道这个方法"可归因。

- **记忆系统**：设计 L1 工作记忆 + L2 短期事件环 + LTM 长期记忆三层架构，按作用域分层（对话内结论/引用隔离，跨对话情节与语义记忆按用户共享）；LTM 以 SQLite 为唯一事实源，情节记忆零 LLM 成本结构化落库、语义记忆覆盖式 UPSERT 避免矛盾，蒸馏双保险触发绕开"无可靠会话结束时机"，向量检索三级降级（Qdrant → 本地余弦 → 键匹配）使记忆链路不依赖向量服务可用性。
