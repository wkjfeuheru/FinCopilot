## 可直接粘贴的版本

**金融投研 Copilot（FinHarness）　Agent 开发　2026.08–至今**

**项目描述**：面向个人投研场景的自主研究 Agent。给定一句自然语言研究需求（如"对比贵州茅台与五粮液当前估值，哪只更贵"），系统自主完成 规划 → 多源取数 → 计算 → 成稿 → 独立复核 的完整闭环，产出带图表、带数据来源附录的 Markdown/docx 研报。项目针对 LLM 金融应用的三处信任缺口设计：**数字不可回溯（幻觉）**、**产出无人复核（单点错误）**、**长链路上下文与成本失控**；以"每个结论性数字都能回溯到具体接口与数据指纹"为硬约束，把研报从"看起来完整的文本"变成可审计的证据链。规模：14.7K 行 Python + 2.4K 行 TypeScript，30 个工具、4 个投研场景技能包、855 条离线测试。

**技术栈**：Python 3.13 · asyncio · FastAPI + SSE · Pydantic v2 · pandas / pyarrow · SQLite + Parquet · tiktoken · AST 白名单表达式引擎 · React 19 + TypeScript + antd · akshare / tushare / Tavily / 东方财富研报 · 多 Provider 双协议（OpenAI 兼容 + Anthropic 兼容，6 家厂商）

- **可信数据底座**：以"结论性数字零幻觉"为硬约束设计数据面——单一数据门面下挂 adapter 防腐层（akshare→tushare 自动降级，降级源按真实 endpoint 隔离、不互相污染缓存）、SQLite 索引 + Parquet 双级缓存（key = `sha256(接口|规范参数|数据日期)`，TTL 按语义分级 1d / 7d / 365d，已沉淀 500+ 数据切片）与引用溯源注册表（cid 递增 + sha256 数据指纹）。每个数字都可定位到"接口 / 标的 / 参数 / 数据指纹 / 是否命中缓存"；成稿管道再做一次无来源数字校验并就地标记 `[!无来源:n]`，把"幻觉"从不可观测的模型行为转成可被测试断言的结构化信号。

- **成本优化：前缀缓存 A/B 实测全价 token -67%**：定位到"动态状态（计划/结论/召回/摘要）拼进 system prompt，导致请求前缀每轮都变、整段历史按全价重算"的成本根因，将状态改为请求末尾的临时消息，使请求结构收敛为 `[静态 system] + 历史 + [状态尾注]`，每轮迭代的公共前缀即上一轮全部内容。自建 A/B 测量脚本（仅 monkeypatch 回旧布局，其余代码路径完全一致，保证同类可比），两次独立运行结果一致：**前缀缓存命中率 30% → 78%，全价 token 25.4K → 7.4K（-67%）**；缓存命中单价约为未命中的 1/10，故实际输入成本降幅大于 token 降幅。

- **上下文工程：入窗口前瘦身 + 超预算自动压缩**：工具结果进上下文前按 token 实算裁剪（行数 + 列数自适应收缩，K 线单结果 ~50K → ~1K token），窗口占用用 tiktoken 实算，并在轮次间隙触发分段累积摘要压缩（保留计划 / 结论 / 最近 2 轮原文，逐级收紧至 0 轮确保压缩后确实回到预算内；摘要调用失败降级为计数式摘要，绝不阻塞会话）。落地时修掉两处只在真实长任务中暴露的缺陷：**"轮"必须按模型往返而非 user 消息计数**（否则"单条长指令"式的研究任务永不触发压缩，恰在最需要时失效）、**压缩切点必须落在 assistant 帧**（否则会留下未被声明的 tool_result，OpenAI 兼容端点直接 400）——两点均以回归测试钉死。

- **风险终审子 Agent：用独立上下文抓作者自己看不见的错**：把"复核"做成系统属性而非模型自觉——报告工具内部**强制**触发终审子 Agent，其工具集由契约派生（仅 `permission=READ` 且属数据/通用组，结构上拿不到写入、META 与交互工具，因而无法自我授权、无法递归派生），且**能自行重新取数核对**报告中的关键数字。真实运行中抓到同一份报告 ROE 前后矛盾（17.72% vs 16.75%）、近一年收益率偏差（-12.43% vs -15.89%）等问题。工程细节：按被复核正文 sha256 闩锁复用意见（修订循环不重复付费）、复核异常一律降级为显式"未经独立复核"警告而不影响报告本体（`ok=True`）、终审结局（done / reused / unreviewed / skipped）作为独立审计事件落账，使"已交付但未复核"在审计日志中可见。

- **Agent 评估体系：从"看起来对"到可复现打分**：自建四维度评估（任务完成率 0.4 / 推理路径正确性 0.25 / 效率 0.15 / 安全性 0.2）加权综合分 + **红线门禁**（红线用例失败、或声明的高危调用未被拦截，本次即整体不通过）；轨迹逐轮记录 Thought/Action/Observation，且**连未执行的调用也记录**（deny 拒绝、懒加载未激活、循环兜底），因而能区分"被拦住了"与"根本没尝试"——这是安全维度唯一可信的口径。判定看行为模式而非字面文本（模型输出有方差），题库由 94 题人工用例设计翻译为可自动判定用例（含 19 条 red-line）。CI 分三层控制真实模型开销：push 跑 855 条离线测试（0 成本）、每夜跑核心冒烟、手动跑全量。

- **声明式量化能力：把"禁止任意代码执行"做成产品约束**：量化场景不给模型代码执行权，改自研基于 `ast` 白名单的因子表达式引擎（时序 / 横截面 / 逐元素三类算子 + 窗口与嵌套深度上限；属性访问与下标在解析期即被拒绝，全程不触碰 `eval`/`exec`），并让回测工具把研究纪律写成代码强制：样本按时间顺序切分（严禁随机切分）、买入持有基准始终参与、成本与滑点按换手率计提、候选因子试验次数上限 50（超限直接失败，而非静默放任数据窥探）、结果明确给出是否跑赢基准而非掩盖失败。

- **治理层：可解释的判定链 + 不可卸载的审计**：权限门按 `deny 规则 > 模式回退 > 路径白名单` 三级判定，拒绝结果回填结构化解释（命中第 N 条规则）供模型自纠；审计链对每次受治理调用落一行 JSONL（行缓冲即时 flush，进程异常退出也不丢记录），action 细化到 `denied / confirm_denied / confirm_timeout / aborted / compact / review`。引入联网检索后对信任边界变化做了显式处置：第三方文本以 `<web_result>` 围栏包裹并声明为"不可执行引文"，本机唯一出站路径（研报 PDF 抓取）加私网阻断（逐跳重校验重定向，拦 loopback / 私网 / 云元数据）+ 大小与时长上限 + 有界重试。主动**不发布** `run_python` 任意代码执行：评估后认定"同用户子进程不构成安全边界"，其收益与 `calc_metrics` 高度重叠，不以演示级隔离冒充安全。
