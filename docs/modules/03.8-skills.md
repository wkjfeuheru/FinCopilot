### 3.8 skills/ —— 投研方法论库

**3.8.1 目录与格式（与 anthropics/skills 兼容）**

> 位置：技能作为**内容资产随包分发**，实际路径为 `src/finharness/skills/`；`settings.paths.skills_dir` 默认解析到该目录，可通过环境变量覆盖。当前已内置 `dupont-analysis` 与 `report-template` 两个样板，其余 6 个按 M4 补齐（frontmatter 解析复用 `yaml`，已在依赖中声明）。

```
skills/
├── dcf-valuation/SKILL.md
├── dupont-analysis/SKILL.md
├── earnings-quality/SKILL.md
├── report-template/SKILL.md
├── industry-framework/SKILL.md
├── valuation-comps/SKILL.md
├── risk-checklist/SKILL.md
└── backtest-protocol/SKILL.md
```

`SKILL.md` 前置 `frontmatter`（YAML）+ 正文（markdown）。frontmatter schema：

```yaml
---
name: dupont-analysis
description: 杜邦三因素/五因素分解 ROE 的归因路径与解读话术。触发词：ROE、杜邦、盈利归因。
inputs:  [symbol 或 cids, 分析期数]
outputs: [三因素分解表 {table:dupont}, 归因结论骨架]
use_cases: [解释同一标的 ROE 历史变化, 解释跨标的 ROE 差异]
examples: ["贵州茅台 ROE 为什么比五粮液高？"]
related_skills: [earnings-quality, valuation-comps]   # 常配套使用的技能（仅提示，不自动加载）
allowed_tools: [get_indicators, calc_metrics, get_financials, get_peers]
content_estimate: 950
version: 1
---
```

- **语义契约**：`description` 负责"选不选它"（短、含触发词，由 `list_skills` 展示）；`inputs`/`outputs` 是接口契约；`use_cases`/`examples` 是选择辅助（`search` 中权重高于 `description`）；`related_skills` 声明组合关系——加载聚合型技能（如 `report-template`）时**只提示**依赖，不自动递归注入，以免违背按需加载与 token 预算。
- **幂等与可观测**：`load_skill` 只注入一次，重复调用返回"已加载（复用）"，对 Agent 重试安全；每次加载留下 `{name, ts, duration_ms, reused}` 记录（`SkillRegistry.load_history()`）。
- `list_skills` 读全部 frontmatter（不读正文）；`load_skill` 注入正文。

**3.8.2 各 Skill 内容要点（正文模板约定）**

| Skill | 正文必须包含 | 产出锚点（模板预留占位符） |
|---|---|---|
| dcf-valuation | WACC 取值逻辑（无风险利率/β/ERP）、三情景增长率、敏感性表模板 | `{table:dcf_sens}` |
| dupont-analysis | 三因素/五因素公式、对比归因步骤、解读话术 | `{table:dupont}` |
| earnings-quality | 检查清单：应收/存货/现金流背离/非经常损益占比 ≥6 项 | `{list:quality_checks}` |
| report-template | 研报结构：核心观点→摘要→分章→估值→风险；图表与引用占位符约定 | `{cite:x}` `{chart:path}` |
| industry-framework | 波特五力→竞争格局→景气跟踪指标三层框架 | `{list:industry_map}` |
| valuation-comps | 可比公司选取标准、PE/PB 修正因子（成长性/ROE） | `{table:comps}` |
| risk-checklist | 生成风险提示的 checklist（≥8 条，含触发条件） | `{list:risks}` |
| backtest-protocol | 样本内外划分、过拟合检查、指标口径 | `{table:perf}` |

**3.8.3 加载与去重**：`load_skill(name)` → 命中 `ctx.loaded_skills` 直接返回"已加载（复用）"；否则注入正文到会话（在下一轮请求中作为一段 `user`/附注内容），并记 ctx。重复调用零成本——这是"多轮方法论复用"的实现细节。
