### 3.8 skills/ —— 投研场景技能库

**3.8.1 目录与格式（渐进式披露）**

> 位置：技能作为**内容资产随包分发**，实际路径为 `src/finharness/skills/`；`settings.paths.skills_dir` 默认解析到该目录，可通过环境变量覆盖。

每个**场景**一个目录，目录内固定三件套：一个 `SKILL.md`（流程/边界/参考索引/输出契约，**不含分析方法本身**）、
`references/`（方法论文件，一个分析维度一份）、`assets/`（该场景的报告模板）。

```
skills/
├── equity-research/          # 个股深度研究
│   ├── SKILL.md              # 场景流程：界定、步骤、何时读哪个文件、输出契约
│   ├── references/           # profitability / growth / health / efficiency / valuation / industry-focus
│   └── assets/report-template.md
├── industry-research/        # 行业研究
│   ├── SKILL.md
│   ├── references/           # lifecycle / value-chain / competition / prosperity / market-space / csf / risk-identification
│   └── assets/report-template.md
├── macro-research/           # 宏观研究
│   ├── SKILL.md
│   ├── references/           # cycle / monetary / fiscal / regulation / external / indicators
│   └── assets/report-template.md
└── quant-factor/             # 量化因子
    ├── SKILL.md
    ├── references/           # single-series / cross-section
    └── assets/report-template.md
```

风险清单（`risk-checklist`）**不再是技能**：唯一消费者是风险终审子 Agent，
现位于 `src/finharness/prompts/risk-checklist.md`，由 `risk_checklist_prompt()` 读取后注入审查系统提示。

`SKILL.md` 前置 `frontmatter`（YAML）+ 正文（markdown）；`references/`、`assets/` 下的 md **无 frontmatter**。
frontmatter schema：

```yaml
---
name: equity-research
description: 个股深度研究场景：财报解读、盈利质量、估值与多标的对比。复杂个股研究任务进入本场景。触发词：个股、财报、ROE、估值、深度研究。
inputs:  [symbol（6位A股代码）, 研究关注点]
outputs: [对话内 markdown 结论, 用户要求报告时经 write_report 成稿]
use_cases: [解读个股财报, 估值判断, 多只个股横向对比]
examples: ["帮我深度分析一下贵州茅台"]
allowed_tools: [get_financials, get_indicators, get_valuation, get_peers, calc_metrics, calc_valuation, make_chart, write_report]
content_estimate: 1400
version: 1
---
```

- **语义契约**：`description` 负责"选不选它"（短、含触发词，由 `list_skills` 展示）；`inputs`/`outputs` 是接口契约；
  `use_cases`/`examples` 是选择辅助（`search` 中权重高于 `description`）；`allowed_tools` 是建议工具（不强制）。
- **文件清单来自目录**：`references/`/`assets/` 下的文件由 `SkillRegistry` 扫描目录得出（`SkillMeta.files`），
  **不在 frontmatter 重复声明**——目录是唯一事实源，杜绝"声明了却不存在"或"存在却未声明"。
- **幂等与可观测**：`load_skill` 对**每个加载目标**只注入一次——目标为 `name`（场景流程）或
  `name/file`（某个参考/模板文件）；重复调用返回"已加载（复用）"，对 Agent 重试安全；
  每次加载留下 `{name, ts, duration_ms, reused}` 记录（`SkillRegistry.load_history()`）。
- `list_skills` 读 frontmatter 并列出可加载文件（不读正文）；`load_skill` 注入某一份正文。

**3.8.2 两阶段加载**

| 阶段 | 工具 | 作用 |
|---|---|---|
| 发现 | `list_skills` | 场景名 + 用途 + 该场景可加载的 references/assets 清单 |
| 加载流程 | `load_skill(name)` | 注入 `SKILL.md`：场景界定、分析步骤、参考文件索引、输出契约 |
| 加载方法 | `load_skill(name, file="references/xx.md")` | 注入单个方法论文件（按需，一单一两份） |
| 加载模板 | `load_skill(name, file="assets/report-template.md")` | 用户要求成稿时，按模板组织报告 |

底层是 `SkillRegistry`（`tools/meta/skills.py`）：启动扫描 `skills_dir/*/SKILL.md`，畸形技能跳过不致命；
`search` 按 name +4 / use_cases·examples +3 / description +2 加权；`load` 对每个目标幂等。
每次工具调用新建一个 registry（读盘，无共享单例），因此内容更新即时生效。

**3.8.3 四个场景**

| 场景 | 界定 | 主要方法论（references） |
|---|---|---|
| `equity-research` | 研究对象是个股，任务超出单点查询 | 盈利能力与质量核查、成长性、财务健康、运营效率、估值（DCF/可比）、行业差异化速查 |
| `industry-research` | 研究对象是行业本身 | 生命周期、产业链、竞争格局、景气度、行业空间、关键成功因素、行业风险 |
| `macro-research` | 研究对象是宏观环境/政策/外部冲击 | 经济周期、货币政策、财政政策、监管环境、外部环境、核心指标速查 |
| `quant-factor` | 检验"规律是否存在于数据" | 单股序列（时序因子与择时）、横截面（分组与 IC/ICIR） |

**场景路由**：agent 依据各 SKILL.md 的 `description` 自主判断；系统提示"技能与产出"节点名四个场景。
简单问答与单点查询不加载场景技能；用户未指明研究维度时，先 `ask_user` 确认关注点。

**3.8.4 回测与报告的归属**

- **回测纪律**（样本内外时序划分、禁样本外调参、试验次数上限、必比买入持有）写在 `quant-factor/SKILL.md`；
  `run_backtest` 是工具层（M3 计划），SKILL.md 写明调用与参数；判读口径分列两份 references。
- **报告模板**在每个场景的 `assets/`；成稿时模型读模板 → 组织内容 → `write_report`，
  报告管线（引用编号、附录、无来源标注、docx 导出）**保持场景无关**。
