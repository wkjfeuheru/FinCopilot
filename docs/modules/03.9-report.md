### 3.9 研报生成管道

**职责**：把模型产出的大纲/正文渲染成带引用附录、带嵌入图表的 Markdown，再导出 docx；执行"无引用数字校验"。

**3.9.1 管道（pipeline.py）**

```python
class ReportPipeline:
    def __init__(self, *, templates: TemplateDir, cite: CitationRegistry,
                 exporter: DocxExporter, settings: Settings): ...
    async def render(self, outline: ReportOutline) -> ReportArtifact:
        # ① 校验 outline：每个小节含 cite 引用列表 & chart 列表（缺失 → ReportValidationError 精确提示）
        # ② 渲染层：场景模板（各场景 assets/report-template.md，模型按模板组织内容）+ 内置结构
        # ③ 引用注入：正文 {cite:cit_000001} → 替换为 [n] 上标，并收集 appendix
        # ④ 图表注入：{chart:output/charts/x.png} → 相对路径核对存在性，缺失 → 占位警告
        # ⑤ 无引用数字校验：正则抽取正文"数字+单位"片段，检查所在段落含 cite 标记，无 → 注入 [!无来源:n] 警告并收集
        # ⑥ 导出：Markdown 主文件 output/<topic>_<YYYYMMDD>.md → docx（python-docx）
        # ⑦ 附录：尾部追加 §数据来源（cite.to_appendix_md 全量）与 §免责声明
        ...
```

**3.9.2 模板与占位符约定（skills 场景资产）**

- 场景报告模板：`skills/<场景>/assets/report-template.md`（个股/行业/宏观/量化各一份）；核心观点（每观点要求带 cite）→ 场景摘要 → 分析章节 → 估值/结论 → 风险提示 → 附录。
- 图表占位符 `{chart:<绝对或相对路径>}`；引用占位符 `{cite:<cid>}`。报告正文的表格/列表由模型直接写成 markdown（不再使用 `{table:}`/`{list:}` 占位符——管线只渲染 cite 与 section 图表）。
- **命名规范**：`output/<topic>_<YYYYMMDD>.md/.docx`；topic 由模型建议、CLI 预检（非法字符替换为 `_`）。

**3.9.3 docx 导出（docx_export.py）**

- python-docx：标题层级映射（`#`→Heading1 … `####`→Heading4）；中文正文宋体/微软雅黑、标题黑体，set eastAsia 字体；表格用 `Table Grid` 样式；图片按宽度适配（>6in 缩到 6in）；段落引用标注保留 `[n]`。
- 导出失败：返回结构化错误 + 保留 markdown 兜底产物，可手工转换（PDF 转换可选，不在主线）。

**3.9.4 成稿后的风险终审（与 §3.10 的接口）**

- `write_report` 在 `export()` 成功后自动调用 `Coordinator.review_risk()`（§3.10），把复核意见并入 tool_result，并由 `review.py` 落盘 `output/<topic>_<YYYYMMDD>.review.md`。终审编排（闩锁、降级、解析、文案）实现在 `coordinator/review.py`，`write_report` 内一行调用——触发点不变，仍为唯一入口。
- 送入复核的是渲染产物正文（截掉"## 附录：数据来源"）——附录是引用表，对风险判断无增量。
- 复核失败一律降级为返回文本里的一行警告，**报告本体不受影响**（`ok=True`）。
- 终审结局（done/reused/unreviewed/skipped）经 `ToolResult.metadata` 声明，`AuditHook` 落一行 `action="review"` 审计记录（§3.7.3）；同一份元数据里的未结事项由 loop 记入会话状态。
- **sidecar 不是交付物**：它只承担闩锁与取证，不入 `attachments`、结果里不给路径、报告正文不写终审字样。边界与严重度判定见 §3.10.7。
