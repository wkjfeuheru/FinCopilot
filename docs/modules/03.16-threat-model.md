# FinHarness 威胁模型（多租户）

> **来源**：《生产环境隔离与多租户加固方案》Phase 2 的收尾项——把 README 与
> 既有模块文档里"单用户本地工具、演示级隔离"的定位，改写为**多租户威胁模型**。
> **性质**：声明式文档，不含代码。它逐条标注哪些是**强制边界**（可以依赖的、
> 结构性成立的性质），哪些是**启发式护栏**（降低风险的检查，但不是边界）。
> **读者**：部署方（判断是否可以把服务开放给互不信任的用户）与后续开发者
> （判断一个改动是否削弱了某条边界）。

---

## 0. 一句话

系统面向的是**互不信任的多租户**：租户数据必须彼此不可达，租户输入不可信。
实现已从"单用户本地工具"向前走了（认证、每用户命名空间、隔离计算 worker），
本文件把**当前实际成立的边界**与**仍只是护栏的东西**区分清楚，避免把护栏
当成边界来依赖。

**信任等级**：不处理刻意构造的对抗性输入的承诺**已作废**。联网检索与研报
全文会把第三方内容带进模型上下文；多租户会把互不信任的请求带进同一进程。
以下边界按此前提设计。

## 2. 强制边界（结构性成立，可依赖）

这些性质由**架构**保证，而非由某段检查的"正确执行"保证。任一改动若削弱它们，
视为破坏隔离。

1. **密钥与租户数据库不在 agent 可达树内。** `state_dir` 与 `output_dir`／
   `cache_dir` 分离，且**加载期强制**：把状态文件配到可达目录内会直接启动失败
   （见 `Settings._validate_state_is_not_agent_reachable`）。这是对所有进程内
   读写路径生效的边界，而不只是对代码执行。
2. **每租户命名空间。** `output_dir` 与 `cache_dir` 都按 `user_id` 派生
   （`scoped_settings`）。缓存文件名是请求形状的哈希，可被同租户推算——因此
   "读不到"由**目录分离**强制，而不是靠猜不到文件名。
3. **可达面收敛为唯一来源。** 工具、`/v1/artifacts` 与权限门都只能问
   `Workspace`（`src/finharness/workspace/`）要可达性。写面是读面的子集，
   `state_dir` 与 `cache/` 根本身不可达。见 `03.15-workspace.md`。
4. **无代码执行原语。** 工具层不含 `subprocess`/`os.system`/裸 `eval`/`exec`；
   `run_python` 刻意不发布；唯一接受模型表达式的地方（`run_backtest.factor_expr`）
   走 AST 默认拒绝白名单。守卫测试见 `tests/workspace/test_no_execution_boundary.py`。
5. **隔离计算 worker 是可选的独立边界。** 配了 `compute.remote_worker_url` 时，
   重活（当前是 docx 导出）在**无状态 worker** 执行：无 `/data` 挂载、无 Provider
   密钥、只在 `compute` 内网可达，经 HMAC 签名接口领任务，未知 `kind` 一律失败
   ——任务包是数据，不是可执行代码。见 `03.15-workspace.md` §3.15.5。
6. **单租户注入必须显式。** `create_app(data_access=...)` 会静默关闭每用户命名
   空间，因此必须同时给出 `single_tenant=True`，且远程监听下**被拒绝**。
   （`tests/server/test_tenant_mode.py`）
7. **租户数据生命周期覆盖四处。** 导出（可携带权）与抹除（遗忘权）同时覆盖
   记忆库、向量库、产物/缓存文件、审计 JSONL——只删数据库会留下假象。
   （`tests/server/test_tenant_lifecycle.py`）
8. **/metrics 在远程暴露下必须带令牌。** 启用 metrics 但未配 `metrics_token`
   时启动失败，避免公网无鉴权读取运营指标。

## 3. 启发式护栏（降低风险，但不是边界）

依赖这些做安全边界的代码是错的。它们的作用是"挡住天真攻击"与"让异常可见"。

| 护栏 | 它挡什么 | 它**不**挡什么 |
| --- | --- | --- |
| deny 规则扫描（交易意图正则） | 提示注入把"下单"写进数据参数 | 别的注入模式；启发式必漏报 |
| 围栏 + 语法中和（`<web_result>`） | 第三方文本伪造围栏语法 | 内容本身的指令（只声明"这是引文"） |
| 权限门确认 | 未经用户同意的写与外发 | 用户点了"同意"之后的一切 |
| `/v1/ready` 依赖探活 | 依赖不可用时摘除实例 | 依赖"能连但语义错误"的情形 |
| 治理事件计数（`governance_events_total`） | — | — （它是**可观测性**，不是拦截） |
| 出站 SSRF 防护（`pdf_fetch`） | loopback/私网/元数据地址；逐跳重定向重校验 | DNS-rebinding（请求前解析，非固定对端） |

## 4. 已知残余风险（记录在案，未处理）

每条都明确"为何可接受"或"触发条件"，避免无意识遗忘。

1. **DNS-rebinding 面**：研报全文本机抓取在请求前解析主机并校验，未固定对端。
   见 `03.4`。触发条件：需要更强的出站保证时改为 IP 直连 + 固定 Host。
2. **联网检索的 SSRF 面为零但有隐私代价**：`web_search` 由 Tavily 服务器发出，
   查询对检索服务可见，内网地址抓不到。这是**设计取舍**，非缺陷。
3. **确认门依赖用户理性**：用户在确认对话框点"同意"后，该操作不再被拦。确认门
   是"让用户知情"，不是"替用户判断"。
4. **单进程部署**：状态是进程内 SQLite，不可横向扩容（应用侧单副本）。计算
   worker 无状态可扩容。多副本会破坏限速与会话的进程内计数语义。
5. **启发式护栏会漏报**：deny 正则、静态沙箱扫描（无调用点）都只挡天真攻击。
   这不是"待补的洞"，而是这些机制的性质——**它们本就不该被当边界**。

## 5. 越权回归（持续验证）

以下测试把关键边界钉死，任一被破坏即 CI 失败。它们是"边界仍然成立"的证据，
而不是一次性验收：

| 边界 | 测试 |
| --- | --- |
| 跨租户缓存/产物不可读 | `tests/server/test_isolation.py`（含按已知哈希路径的尝试） |
| 状态目录不可达 | `tests/config/test_settings.py`（模型级校验） |
| 可达面契约 | `tests/workspace/test_contract.py`、`test_no_execution_boundary.py` |
| 单租户注入显式 | `tests/server/test_tenant_mode.py` |
| 计算边界（进程/产物/租约） | `tests/compute/`、`tests/server/test_compute_internal_api.py` |
| 租户导出/抹除覆盖四处 | `tests/server/test_tenant_lifecycle.py` |
| /metrics 令牌门禁 | `tests/server/test_api.py`（`-k metrics`） |
| 治理事件可告警 | `tests/observability/test_governance_metrics.py` |

## 6. 部署方检查清单（开放公网前）

- [ ] `server.allow_remote=true`（强制：回环绑定＋`permission.default_mode=default`＋`secure_cookie=true`＋远程 worker 地址）。
- [ ] `auth.allow_register=false`（默认已关；用 `FINH_AUTH_ADMIN_BOOTSTRAP` 产生首个管理员）。
- [ ] 若启用 `observability.metrics.enabled`，设 `server.metrics_token`（否则启动失败）。
- [ ] TUN/TLS 终止在反代（Caddy）；应用只绑回环，不直接暴露端口。
- [ ] `state/` 位于只对应用可读的卷（如 `/data`），不进镜像、不进 Git。
- [ ] 计算 worker 与 app 分容器、共享 HMAC 密钥、不共享 `/data`。
- [ ] 建立告警：`governance_events_total` 上升、`/v1/ready` 非 200、拒绝率异常。
- [ ] 明确数据保留期，并演练一次租户导出与抹除。
