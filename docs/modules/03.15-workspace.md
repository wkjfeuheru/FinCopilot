> `tests/workspace/test_no_execution_boundary.py`（11 例）

## 3.15.1 为什么需要这一层

在此之前，"哪些路径可达"由**六处各自拼装**：

| 位置 | 曾自行拼装的根 |
| --- | --- |
| `tools/generic/files.py` `read_file` | `output/` + `cache/parquet` |
| 同上 `write_file` | 仅 `output/` |
| `tools/generic/pdf.py` `read_pdf` | `output/` + `cache/pdf` + `cache/parquet` |
| `tools/meta/summarize.py` | 同 `read_pdf` |
| `server/api.py` `/v1/artifacts` | `output/<user>/` + `cache/parquet` + `cache/pdf` |
| `permissions/gate.py` | 白名单 `output/`、拒写整棵 `cache/` |

它们**大体一致，但是各自书写的**。后果有三类：

1. **任一处的错误都是一个绕过点**，且修一处不等于修全部；
2. **范围会无意识漂移**——`read_pdf` 能读 `cache/pdf` 而 `read_file` 不能，
   这类差异既可能是 bug，也可能让一个工具成为另一个的绕过通道；
3. **门与工具可能对同一操作得出不同结论**——隔离方案 G6 记录的"白名单根
   宽于工具实际根"正是这种分叉的产物。

`Workspace` 把可达性收敛成**唯一来源**：工具、端点与权限门都只能问它。

## 3.15.2 契约（可执行，非描述性）

| 面 | 范围 |
| --- | --- |
| **可读** | `output_dir/`、`cache_dir/parquet/`、`cache_dir/pdf/` |
| **可写** | 仅 `output_dir/` |
| **不可达** | `state_dir/`（主密钥、用户库、对话库、加密配置库）、`cache_dir/` 根本身 |

三点设计理由：

- **缓存整棵树不可写、且只开两棵子目录可读。** 缓存的 lookup 键跨用户共享，
  模型侧一次写入即可替换他人稍后命中的载荷（缓存投毒）；而 `cache` 根下的
  `index.db` 是跨租户的查找索引，不属于"按句柄取回的材料"，因此连读都不开。
- **写面必须是读面的子集**（由 `test_writable_roots_are_a_subset_of_readable_roots`
  守住）：任何可写位置都必须先可读，否则会出现"写得进去但读不回来"的黑洞。
- **`state_dir` 必须不可达。** 这是 P0-3 把密钥搬家的全部意义；此处把它写成
  契约断言，使回退（例如把 `state_dir` 配到 `data_cache` 下）无法通过测试。

## 3.15.3 强制手段的现状与下一步

**当前仍是应用层检查**：`resolve()` 展开符号链接与 `..`，再判包含关系
（`Workspace._resolve`）。它挡得住路径穿越，也挡得住持久化软链，但**不是内核级
边界**——它依赖这段 Python 正确执行。

真正的边界应由命名空间提供：把 `mount_plan()` 列出的路径以 `rw`/`ro` 挂载进一个
受限执行域，**其余一律不挂载**。那时 `state_dir` 不是"被检查挡住"，而是"根本不在
命名空间里"，任何 Python 层的判断失误都不再构成越权。

`mount_plan()` 已经按契约推导好了（读面 `ro`、写面 `rw`，由根列表推导而非另写），
并由 `test_mount_plan_marks_state_and_cache_root_as_unmounted` 守着"密钥与 cache 根
必须在清单之外"。把它接到实际容器是 Phase 2 的部署工作。

## 3.15.4 可达面里没有代码执行（P1-2 的实际结论）

原路线图的 P1-2 是"执行沙箱（容器/受限账户 + 密钥目录不可达）"。实施前先核实它
要围住什么，结论是**没有对象**：

- 工具层（agent 唯一能触达的代码）不含 `subprocess`、`os.system`、裸
  `eval`/`exec`；`run_python` 刻意不发布，注册表里没有执行类工具。
- 唯一接受模型表达式的地方是 `run_backtest` 的 `factor_expr`，由
  `factor/engine.py` 以 **AST 白名单**求值：`_validate` 是默认拒绝（未知语法
  直接抛错），禁止属性访问与下标，函数名须在白名单内。

因此给"不存在的代码执行"建容器，得到的是一个空容器，而文档里会多出一条
"沙箱已完成"——那是用配置冒充边界。改为把**让 P1-2 不必要的那条性质本身**写成
守卫（`tests/workspace/test_no_execution_boundary.py`）：

- 扫描工具层源码，禁止执行原语（区分裸内置调用与 `re.compile` 这类属性调用，
  避免误报把守卫噪音化）；
- 断言注册表里没有执行类工具名；
- 断言因子引擎不是 `eval`，并用逃逸样本（`__import__`、`__subclasses__`、`open`、
  下标、`lambda`）验证解析期即拒，同时用一个合法表达式证明不是"全拒"。

**代价与触发条件**：这组守卫的代价是"未来加执行类工具会失败"。这正是意图——
那一刻 P1-2 从"不必要"变成"必要"，而失败会明确告诉你。

**P1-2 剩下的部分**（把整个应用放进容器：非 root、只读 rootfs、drop
capabilities、按 `mount_plan()` 挂载）属于部署形态，记在方案 Phase 2。

## 3.15.5 隔离计算通道已接线（P1-3 的第一条真实路径）

`mount_plan()` 把可达面推给了部署，但"重活离开主进程"还需要一条真实的任务通道，
否则 worker 容器只是一段没有调用方的代码。这条通道现在接的是 **docx 导出**——
它是当前唯一"输入受控、输出是二进制文档、且值得离开主进程"的操作：

- **主服务**（`compute/executor.py` 的 `RemoteComputeExecutor`）把任务打成 ZIP 入队
  `state/compute_jobs.db`，轮询结果，再把 worker 回传的 blob **按服务端派生的
  `(user, conversation, job)` 目录**落盘（见 `allocate_artifact_dir`）。worker 自报
  的任何路径都不被采信。
- **worker**（`compute/worker.py`）是个无状态拉取循环：无 `/data` 挂载、无 Provider
  密钥、只在 `compute` 内网可达。它经 HMAC 签名的内部接口领任务，未知 `kind` 一律
  失败——任务包绝不是"可执行代码"，只是数据。
- **工具侧**（`tools/fin/writer.py`）声明 `needs_compute=True`，由循环注入会话绑定的
  `SessionCompute`（`user_id`/`conversation_id` 只在此处可知，工具不该自己拼）。
  图表是本地文件而 worker 不挂载 output，因此渲染前把图片按**内容哈希**收进任务包、
  引用改写为包内名，worker 再解析回绝对路径——否则隔离路径会把图表静默降级成
  "图片缺失"。

**为什么是"可选"而非"必选"**：只有在 `compute.remote_worker_url` 配好时才启用通道；
未配（本地、CLI、Railway 单服务）时注入 `None`，工具回退进程内导出。声明的是
"可以外包"，不是"必须外包"——把重活发给一个不存在的 worker，只会让本地每次导出拖到超时。

## 3.15.6 单租户注入必须显式（P1-6）

`create_app(data_access=...)` 会让全体用户共用一份数据面，静默关闭每用户命名空间
（隔离方案 G9）。现在它是一个**必须写出来的声明**：

- 不给 `single_tenant=True` 就注入 → 启动即 `ValueError`；
- 在 `server.allow_remote=true`（多租户）下，即便声明了也拒绝 —— 多租户部署里
  "静默共用一个数据面"是隔离失效，不是配置选项。

测试：`tests/server/test_tenant_mode.py`（4 例）。
