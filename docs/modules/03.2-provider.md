### 3.2 provider/ —— 模型提供层

**职责**：把厂商差异（消息格式 / SSE 事件名 / 鉴权 / 价格）归一化为 §2 的 `StreamChunk` 事件流与统一消息格式。

**统一消息协议（层内规范，与厂商无关）**：

```python
@dataclass
class Msg:
    role: Literal["system", "user", "assistant", "tool_result"]
    content: str | None                    # 文本正文
    tool_uses: list[ToolUse] | None = None # role=assistant 且本轮调工具时非空
    tool_results: list[tuple[str, str]] | None = None  # (call_id, content)
```

- **system→厂商**：anthropic 兼容端点把 system 移出 messages 用 `system` 顶层参数；openai 兼容端点降级为 `messages[0] = {role:system}`。
- **tool_result→厂商**：anthropic 端点需 `user` 角色消息包裹 tool_result block；openai 兼容端点用 `tool` role。
- **assistant→厂商**：含 `tool_use` 的回合须按 content_block 结构还原（anthropic 用 `tool_use` block + `tool_result` block；openai 用 `tool_calls`）。

**接口**：

```python
class Provider(ABC):
    # 归一化流式：消费厂商 SSE，产出 StreamChunk 序列
    async def stream(self, *, system: str, messages: list[Msg],
                     tools: list[dict], usage: ModelUsage) -> AsyncIterator[StreamChunk]: ...

class AnthropicCompatProvider(Provider): ...   # /v1/messages, x-api-key + anthropic-version 头
class OpenAICompatProvider(Provider): ...      # /v1/chat/completions, Bearer
def build_provider(cfg: ProviderCfg, http: httpx.AsyncClient) -> Provider: ...
```

**AnthropicCompat 端点事件映射**（直连解析，不依赖 SDK）：

| 厂商事件 | 归一化事件 | 说明 |
|---|---|---|
| `content_block_start`(type=tool_use) | `TOOL_USE_DELTA` | 建立 tool_use 缓冲区 |
| `content_block_delta`(input_json_delta) | `TOOL_USE_DELTA` | 追加 JSON 片段 |
| `content_block_delta`(text_delta) | `TEXT_DELTA` | 追加正文 |
| `message_delta`(usage/stop_reason) | （不产出事件） | 仅更新 usage 与 stop_reason，不结束消息 |
| `message_stop` 或正常 EOF | `MESSAGE_END` | 收尾，携带最终 usage 与完整工具调用；每次成功流仅一次 |
| `error` | 抛出 `AuthError` / `RateLimitError` / `ServerError` / `NetworkError` | 按错误类型分级抛出，不产出 `StreamEvent.ERROR` |

- 解析器：`event_stream.py` 维护增量片段并将工具调用归并为 `ToolUse(call_id, name, args)`；流中工具与文本增量统一通过 `ToolUseDelta`、`TEXT_DELTA` 产出。
- `message_delta` 仅更新 `usage` 与 `stop_reason`；只有收到 `message_stop` 或正常 EOF 才产出 `MESSAGE_END`。
- 每次成功的流式请求恰好产出一个 `MESSAGE_END`，其中包含最终 usage 与完整工具调用。
- **错误分级与抛出**：`RateLimitError(429)`、`AuthError(401,403)`、`ServerError(5xx)`、`NetworkError(超时/断连及无效响应)`。
- Provider 错误事件直接抛出上述错误类型，绝不产出 `StreamEvent.ERROR`。
- **SSE 超时**：首字节超时 30 秒、块间隔 idle 60 秒，可按 provider 配置覆盖。

**OpenAICompat 端点**：DeepSeek 使用 `/v1/chat/completions`；请求体 `tools` 转 `function` schema，响应解析 `tool_calls` 与 `delta.content`，usage 取 `prompt_tokens/completion_tokens`。鉴权使用 `Authorization: Bearer`。Kimi 与 GLM 的默认配置使用 Anthropic 兼容协议，端点为各自 `base_url` 下的 `/messages`（默认完整路径为 `/anthropic/v1/messages`），鉴权使用 `x-api-key` 与 `anthropic-version`。测试通过 HTTP mock 保持离线，不调用真实厂商 API。
