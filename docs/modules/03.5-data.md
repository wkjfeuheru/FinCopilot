### 3.5 data/ —— 数据适配、缓存与溯源

**职责**：对外提供唯一数据门面 `DataAccess`；内含 adapter 防腐层、LocalCache、CitationRegistry。**这一层是"数据零幻觉"与"降级不感知"的工程载体。**

**3.5.1 门面与接口（DataAccess）**


- **降级编排（DataAccess 内）**：对每个语义方法按 `settings.data.adapter_order` 顺序尝试；捕获 `AdapterError` 后标记降级并在 RawData.endpoint 上记录真实来源（如 `tushare:pro.daily`），再尝试下一适配器；全部失败 → 抛 `DataUnavailableError`（含各源失败原因汇总），由工具转 ok=False。**顺序即优先级**：把某个源排在前面，后面那个就只在它失败或不支持该语义方法时才会被用到（见 §3.5.5 的取舍理由）。
- **字段级映射表**：`data/mapping.py` 常量表定义各源列名→内部列名的双向映射，作为单一事实；新增接口时只扩表不散改代码。
- **归一化列名（内部契约）**：行情 `date,open,high,low,close,volume,amount`；指标与财报列保留中文语义并统一转为 `指标名+报告期` 长表（doc 中列明映射规则即可，细节实现期落 `mapping.py`）。
- **雷区**：akshare 接口是同步阻塞库且偶发慢 → 一律 `asyncio.to_thread` 执行 + 单次 fetch 超时由工具层 timeout 兜底；akshare 列名/行为变更由"接口冒烟测试"（§8）监控。

**3.5.3 LocalCache（cache.py，SQLite 索引 + parquet 数据）**

- 目录布局：`data_cache/index.db` + `data_cache/parquet/<YYYY-MM>/<cache_key>.parquet`。
- **cache_key**：`sha256(f"{endpoint}|{规范参数json}|{数据日期}")[:16]`；`endpoint`=真实来源名（akshare:xxx / tushare:xxx），保证降级源不互相污染。
- **SQLite 表（详细 DDL 见 §4.1）**：`cache_index(cache_key PK, endpoint, params_json, data_date, rows, created_ts, ttl_days, file_path)`。
- 读流程：`cache_key 命中 && now-created_ts ≤ ttl_days` → 读 parquet → 返回；miss/过期 → 走 adapter，写回。写流程用 `INSERT OR REPLACE`，天然幂等。
- TTL 语义（settings.data.cache_ttl_days）：quote 按交易日 1 天；kline 1 天（K 线随行情收盘更新）；indicators 7 天（报告期数据稳定）；financials 365 天（按报告期，跨财报季由参数中的 years/report_period 区分）；announcements 7 天。
- 节流：akshare 两次调用间隔 ≥ throttle_seconds（内存级 `asyncio.Lock`+时间戳，进程内生效）。
- 命中统计接口：`stats() -> CacheStats(entries, hits, misses, hit_ratio)`，供 `/cache` 命令。

**3.5.5 同花顺（iFinD / Fuyao）MCP 适配器**

**它补齐的缺口**：akshare 覆盖 A 股行情与一份中文宽表式财报摘要，但拿不到结构化的三表字段（`operating_income`/`assets_total`/`act_cash_flow_net`…）、按报告期的完整财务指标、同花顺概念指数成分股、横截面估值快照，以及涨停池/龙虎榜/热股榜这类特色数据。

**接入形态**：同花顺以六个 MCP 服务（`a-share`/`a-share-index`/`meta`/`fund`/`futures`/`options`）暴露能力，每个是一个 Streamable HTTP 端点，共用一个 API Key（请求头 `X-api-key`）。

```
DataAccess
  └─ FuyaoMcpAdapter (name="fuyao")
       ├─ typed:  fetch_quote / fetch_kline / fetch_financials
       │          / fetch_indicators / fetch_index_constituents
       ├─ generic: fetch_dataset(service, dataset, params) / list_datasets(service)
       └─ McpHttpClient  ──→  https://fuyao.aicubes.cn/mcp/<service>
            JSON-RPC 2.0 over Streamable HTTP
            initialize → Mcp-Session-Id → notifications/initialized
            → tools/list | tools/call（JSON 与 SSE 两种响应都解析）
```

**两条入口，两种取舍。** typed 方法把结果归一化到本项目**既有的**表格契约，因此
`get_quote`/`get_kline`/`get_financials`/`get_indicators`/`get_index_constituents`
这些工具**一行不改**就获得了新字段与覆盖范围：

| 语义方法 | 归一化目标 | 说明 |
|---|---|---|
| `fetch_quote` | `symbol/date/open/high/low/close/volume/amount`（`MARKET_COLUMNS`） | 快照行不带日期，日期取自信封 `timestamp` |
| `fetch_kline` | 同上，最新在前 | 仅日线；周/月线抛 `NotImplementedError` 交给 akshare |
| `fetch_financials` | 「指标行 × `YYYYMMDD` 报告期列」宽表 | 与 akshare 摘要表同形，故列裁剪的"年度优先"与计算工具都无需特判 |
| `fetch_indicators` | `date` 列 + 中文指标名列 | 端点一次只给一个报告期，故按期发多次请求（`mapping.fuyao_report_periods`，有上限） |
| `fetch_index_constituents` | `symbol`/`name`/`thscode` | 只受理能映射到 thscode 的指数，其余交 akshare |

通用通道 `fetch_dataset` 触达长尾端点（特色数据、基金、期货、期权、估值快照、标的检索）。
其**参数 schema 来自服务端运行时的 `tools/list`**，而非本地手抄——这是关键取舍：上游有
78 个端点，手抄 70 份 schema 意味着那些拷贝会在上游改动时静默过期。

**故障分类**（`AdapterError.retryable`，供回退编排决策）：

| 上游 code | 含义 | 处理 |
|---|---|---|
| `0` | 成功 | — |
| `1001`–`1004` | 参数错误 | 不可重试，换下一个源 |
| `2001`/`2003` | 未认证 / 权限不足 | 不可重试 |
| `3001`/`3002`/`3004` | 标的不存在 / 数据未就绪 / 类型不支持 | 不可重试，视作"这个源现在没有" |
| `4001` | 限流（也可能表现为 HTTP 429） | 可重试 |
| `5001`–`5003` | 服务端 / 上游故障 | 可重试 |

业务失败经 `code` 表达而 **HTTP 状态码恒为 200**，因此只检查状态码会把错误当成数据帧渲染出来；`_unwrap` 是这条路径上唯一的安全网。

**已核实的线上行为**（`tests/data/test_fuyao_smoke.py` 记录，公开文档未涵盖）：标准 Streamable
HTTP 握手；`protocolVersion` 为 `2024-11-05`；响应是 JSON 而非 SSE；**未认证时 `initialize`
仍然成功**，鉴权推迟到 `tools/call` 并以 `code=2003` 表达；每个数据集都带 `inputSchema`，
且若干部署了**实质性默认值**。

**继承默认值的披露。** 上游为若干参数声明了实质性默认——例如 `get_a_share_prices_snapshot`
的 `thscodes` 默认为 `600519.SH,000001.SZ`。调用方省略它时得到的**不是全市场，而是这两只**，
且请求里不留痕迹。因此派发器把"调用方指定的"与"上游默认决定的"分开记录，并在结果头部
披露后者（`未指定、由上游默认决定：…`）。这与本层"数据零幻觉"的口径一致：一个隐含的筛选
条件如果不可见，就会被读成全局结论。

**参数翻译。** 模型知道六位代码，不知道 thscode，因此 `symbol`/`symbols` 在本地译成
`thscode`/`thscodes`（多值以逗号拼接），`start`/`end` 接受 `YYYY-MM-DD` 或毫秒时间戳。
代码→交易所的推导覆盖 A 股号段与已上市基金（ETF/LOF/REITs）；两者都不认识时**拒绝而不是
猜测**——猜错的后缀会让上游返回另一个标的的数据，而那份结果看起来完全正常。

## 附：数据存储设计（原主文档 §4.1 / §4.2）

### 4.1 SQLite（data_cache/index.db）

```sql
-- 缓存索引：数据体在 parquet，SQLite 只做定位与 TTL
CREATE TABLE cache_index (
    cache_key   TEXT PRIMARY KEY,      -- sha256(endpoint|params|data_date)[:16]
    endpoint    TEXT NOT NULL,         -- akshare:stock_zh_a_hist / tushare:xxx
    params_json TEXT NOT NULL,         -- 规范化参数快照
    data_date   TEXT NOT NULL,         -- 数据对应交易日/报告期
    rows        INTEGER NOT NULL,
    cols_json   TEXT NOT NULL,
    created_ts  TEXT NOT NULL,         -- UTC+8
    ttl_days    INTEGER NOT NULL,
    file_path   TEXT NOT NULL
);
CREATE INDEX idx_cache_endpoint ON cache_index(endpoint);
CREATE INDEX idx_cache_data_date ON cache_index(data_date);
```

- parquet 文件命名：`data_cache/parquet/<YYYY-MM>/<cache_key>.parquet`；读路径 = 先查索引取 file_path，避免目录扫描。
- 访问并发：SQLite `check_same_thread=False` + 单写锁（进程内 asyncio 包装，写操作经 `run_in_executor` 排队）；写用 `INSERT OR REPLACE` 幂等。
- 维护：`fin cache --gc` 删除过期条目与孤儿 parquet（过期 = now-created_ts > ttl_days）；每次启动静默执行一次（阈值 >1000 条才触发，避免启动卡顿）。

### 4.2 parquet 数据契约

- DataFrame 序列化前统一列类型（date 列转 `datetime64`，数值列转 float/float64 并置 NaN 统一）；空表（rows=0）不落盘，走"空结果"路径（索引不建、直接返回空 RawData + citation 仍注册，注明 rows=0）。
- 读回时反序列化列名/类型保持一致（mapping.py 负责，避免 ak 返回类型漂移污染缓存命中后的解析）。
