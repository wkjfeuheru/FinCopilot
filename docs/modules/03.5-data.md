### 3.5 data/ —— 数据适配、缓存与溯源

**职责**：对外提供唯一数据门面 `DataAccess`；内含 adapter 防腐层、LocalCache、CitationRegistry。**这一层是"数据零幻觉"与"降级不感知"的工程载体。**

- **降级编排（DataAccess 内）**：对每个语义方法按 `settings.data.adapter_order` 顺序尝试；捕获 `AdapterError` 后标记降级并在 RawData.endpoint 上记录真实来源（如 `tushare:pro.daily`），再尝试下一适配器；全部失败 → 抛 `DataUnavailableError`（含各源失败原因汇总），由工具转 ok=False。
- **字段级映射表**：`data/mapping.py` 常量表定义各源列名→内部列名的双向映射，作为单一事实；新增接口时只扩表不散改代码。
- **归一化列名（内部契约）**：行情 `date,open,high,low,close,volume,amount`；指标与财报列保留中文语义并统一转为 `指标名+报告期` 长表（doc 中列明映射规则即可，细节实现期落 `mapping.py`）。
- **雷区**：akshare 接口是同步阻塞库且偶发慢 → 一律 `asyncio.to_thread` 执行 + 单次 fetch 超时由工具层 timeout 兜底；akshare 列名/行为变更由"接口冒烟测试"（§8）监控。

**3.5.3 LocalCache（cache.py，SQLite 索引 + parquet 数据）**

- 目录布局：`data_cache/index.db` + `data_cache/parquet/<YYYY-MM>/<cache_key>.parquet`。
- **cache_key**：`sha256(f"{endpoint}|{规范参数json}|{数据日期}")[:16]`；`endpoint`=真实来源名（akshare:xxx / tushare:xxx），保证降级源不互相污染。
- **SQLite 表（详细 DDL 见 §4.1）**：`cache_index(cache_key PK, endpoint, params_json, data_date, rows, created_ts, ttl_days, file_path)`。
- 读流程：`cache_key 命中 && now-created_ts ≤ ttl_days` → 读 parquet → 返回；miss/过期 → 走 adapter，写回。写流程用 `INSERT OR REPLACE`，天然幂等。
- TTL 语义（settings.data.cache_ttl_days）：quote 按交易日 1 天；kline 1 天（K 线随行情收盘更新）；indicators 7 天（报告期数据稳定）；financials 365 天（按报告期，跨财报季由参数中的 years/report_period 区分）；announcements 7 天。
- 节流：akshare 两次调用间隔 ≥ throttle_seconds（内存级 `asyncio.Lock`+时间戳，进程内生效）。
- 命中统计接口：`stats() -> CacheStats(entries, hits, misses, hit_ratio)`，供 `/cache` 命令。

## 附：数据存储设计（原主文档 §4.1 / §4.2）

### 4.1 SQLite（data_cache/index.db）

```sql
-- 缓存索引：数据体在 parquet，SQLite 只做定位与 TTL
CREATE TABLE cache_index (
    cache_key   TEXT PRIMARY KEY,      -- sha256(endpoint|params|data_date)[:16]
    endpoint    TEXT NOT NULL,         -- akshare:stock_zh_a_hist / tushare:xxx
    params_json TEXT NOT NULL,         -- 规范化参数快照
    data_date   TEXT NOT NULL,         -- 数据对应交易日/报告期
    rows        INTEGER NOT NULL,
    cols_json   TEXT NOT NULL,
    created_ts  TEXT NOT NULL,         -- UTC+8
    ttl_days    INTEGER NOT NULL,
    file_path   TEXT NOT NULL
);
CREATE INDEX idx_cache_endpoint ON cache_index(endpoint);
CREATE INDEX idx_cache_data_date ON cache_index(data_date);
```

- parquet 文件命名：`data_cache/parquet/<YYYY-MM>/<cache_key>.parquet`；读路径 = 先查索引取 file_path，避免目录扫描。
- 访问并发：SQLite `check_same_thread=False` + 单写锁（进程内 asyncio 包装，写操作经 `run_in_executor` 排队）；写用 `INSERT OR REPLACE` 幂等。
- 维护：`fin cache --gc` 删除过期条目与孤儿 parquet（过期 = now-created_ts > ttl_days）；每次启动静默执行一次（阈值 >1000 条才触发，避免启动卡顿）。

### 4.2 parquet 数据契约

- DataFrame 序列化前统一列类型（date 列转 `datetime64`，数值列转 float/float64 并置 NaN 统一）；空表（rows=0）不落盘，走"空结果"路径（索引不建、直接返回空 RawData + citation 仍注册，注明 rows=0）。
- 读回时反序列化列名/类型保持一致（mapping.py 负责，避免 ak 返回类型漂移污染缓存命中后的解析）。
