### 3.12 server/ —— HTTP/SSE 接口层（FastAPI，v1.1 新增）

**职责**：把 AgentLoop 的内部事件流（文本增量/工具状态/计划/确认/结论）暴露为 **SSE**；管理服务端会话生命周期与 write 确认往返；挂载简易 Web 聊天页。**不承载任何业务逻辑**——所有能力仍来自 engine/tools/data，本层只是传输与编排。

**3.12.1 模块文件与依赖**

```
src/finharness/server/
├── api.py            # FastAPI app 与全部路由（薄控制器，调 sessions/loop）
├── sse.py            # EngineEvent → SSE 帧编组（event/data 行）；响应流对象
├── sessions.py       # SessionRegistry：登记/复用/idle 回收/单飞控制
├── confirm.py        # ConfirmBus：write 工具异步确认通道（Future + TTL）
├── distill_sweeper.py# LTM 懒蒸馏的后台扫描器（§3.6.4「4.1」，与 loop_factory 兜底互补）
└── static/           # React/Vite 构建产物（生产环境由 FastAPI 托管）
```

依赖注入：`run_serve()` 用与 CLI 相同的 `session_deps` 组装一份进程级 deps（cache/cite/gate/hooks/registry/settings 共享），每个 HTTP 会话再由此派生自己的 `AgentLoop + ResearchContext`。技术栈：`fastapi + uvicorn + sse-starlette`（或手写 SSE 生成器，实现自由）。

**3.12.2 SessionRegistry（服务端会话生命周期）**

- 数据结构：`session_id → ServerSession{ loop, ctx, last_active, created, mode, busy }`。
- `ensure_session(session_id?, mode)`：无 id/已过期 → 新建（返回新 id）；命中且未 busy → 复用同 `AgentLoop/ResearchContext`——**多轮连续性语义与 REPL 完全一致**（ResearchContext 跨轮累积、追问增量复用）。
- idle 回收：**惰性淘汰**——`ensure()`/`release()` 各自触发一次 `_evict_expired` 扫描，把 `last_active` 超过 `settings.server.session_ttl_s`（默认 1800）的条目从注册表移除。此前文档所说的"每 60s 后台扫描 → 结束并复用 CLI 退出逻辑（audit session_end + MEMORY merge）"**从未实现**：代码里没有该后台任务，淘汰仅 `del` 字典项，无回调、无 session_end、无记忆合并。（唯一的周期后台任务是 §3.6.4 的 LTM 蒸馏扫描器，它读对话表而非会话表，与这里的会话回收是两件事。）
- 单飞约束：同一 session 正在处理请求时，新请求返回 `409 busy`（不做消息排队，demo 阶段保证状态一致性最简单）。
- 会话上下文复用数据层缓存与 citation 注册表是进程级共享，跨会话也可命中缓存（天然收益）。
- **会话状态只有一个所有者**：会话级的 `citation`/`ResearchContext` 只挂在 `ServerSession.loop` 上，由注册表 TTL 统一回收；进程级只保留**必须跨会话**的两份有界缓存——`conversation_citations`（对话级引用，上限 `context.retention_conversations`）与 `user_data_access`（用户级 DataAccess，上限 `server.user_cache_size`）。此前会话状态在注册表之外另存一份副本，而注册表淘汰够不到它，导致每个会话永久残留一份记忆（含整条 L1 记录）——这是最大的无界内存泄漏点，已由"单一所有者 + 有界缓存"修复。
- **busy 会话可被回收**：idle 回收显式跳过在飞（`busy`）会话以免并发写；但一个被遗弃的请求（流挂了、`release` 没跑到）会让它永久占位，因此 busy 持续超过 `server.busy_timeout_s`（默认 3600）的条目按遗弃回收。缺少 busy 起始时刻时保守地按在飞处理。
- 回收时机：`ensure()`（新请求）与 `release()`（一轮结束）都会触发一次扫描；后者让空闲进程不必等到下一个请求才回收。

**3.12.3 SSE 事件协议（EngineEvent → SSE 帧）**

```
POST /v1/chat/stream      Content-Type: application/json
请求体: { "session_id": "s_xxx"? , "conversation_id": "c_xxx"?, "message": "…", "resume": false }
响应:   text/event-stream（UTF-8，每帧即时 flush）

> 请求体**没有** `mode` 字段（2026-09 修订）：权限模式是部署级设置
> （`settings.permission.default_mode`，`allow_remote=true` 时强制 `default`），
> 不接受按请求指定。此前文档描述的 `mode` 字段从未接到门禁上——它只进了
> 观测日志，与"可升权"的直觉相反，因此已删除而非保留为误导性参数。
>
> `resume` 默认 `false`（见下表后说明）；显式恢复与普通新消息语义不同。
```

| SSE `event` | `data`(JSON) | 语义 |
|---|---|---|
| `session` | `{session_id, conversation_id}` | 会话建立/复用结果；**客户端保存 `conversation_id`**（持久句柄） |
| `state` | `{schema_version, run_id, conversation_id, user_id, revision, phase, turn, …, outcome?}` | **持久化 Agent FSM 公开视图**（`phase` ∈ hydrate/thinking/tooluse/awaitingconfirmation/compact/complete/error）。每完成一次合法转移先落库再发出；additive，既有事件名不变（docs 03.3.12） |
| `plan_progress` | `{revision, done, total, stalled_turns, drift[], mismatch[]}` | 计划进度/目标漂移/能力错配/停滞（每轮工具执行后；**软信号，不阻断调用**，docs 03.3.9） |
| `delta` | `{text}` | 终答/思考文本增量（逐字流式下发） |
| `text_reset` | `{}` | 本轮实为工具调用，客户端丢弃已显示的草稿正文 |
| `tool_status` | `{call_id, name, status:started\|completed\|failed, ok?, duration_ms?, citations?, attachments?, summary?}` | 工具生命周期（含被拒/确认中、产物文件）。**additive** `summary` 是白名单参数投影（`industry`/`symbol`/`query`/`view`/`period`/`top`/`years`/`file`/`tasks`），供前端覆盖条写「正在读取白酒行业表现」；不是 args 原样拷贝，文件正文与密钥不下发 |
| `context_compacted` | `{removed, before_tokens, after_tokens, degraded?, warning?}` | 上下文压缩发生（前端提示可见） |
| `loop_guard` | `{call_id, name, count, action:refused\|would_abort}` | 检测到重复调用。`refused`（第一次违规）回放上次成功结果并提示作答或 `spawn_agent` 拆角度，**前端刻意不展示**；`would_abort`（该调用再次出现）停止继续执行——已有成果则无工具收尾并成功结束，仅无成果才 `loop_detected`（docs 03.3.7 不变量 5） |
| `citations` | `{list:[{cid,tool,symbol,ts}]}` | 会话已积累的溯源（增量时推送） |
| `confirm_request` | `{confirm_id, tool, args_summary, ttl_s}` | **write 类工具等待用户确认**（兼容旧名；交互主通道见 `interactive_request`） |
| `interactive_request` | `{request_id, kind, prompt, options, multi_select?, …}` | 写确认 / `ask_user` 往返；**必须排在**对应的 `state(phase=awaitingconfirmation)` **之后** |
| `answer` | `{text}` | 本轮终答；失败轮次在此回传**部分成果**（docs 03.3.6，前端幂等赋值） |
| `error` | `{kind, message, reason}` | 会话级错误；`reason` ∈ `loop_detected`/`max_turns_exhausted`/`provider_error`，前端据此给友好文案。**用户主动停止不发此事件**（停止不是错误，见 §3.12.8）。循环防护有成果收尾也不发此事件（成功结束，见不变量 5） |
| `done` | `{succeeded, reason?, resumable?, session_id, conversation_id, usage{input/output/cache_hit/cache_miss/cache_hit_ratio}, window_tokens, compactions, tool_calls, retry_count, tool_duration_ms, per_agent, citations, plan?{revision,done,total}}` | 本轮结束；`plan` 使重规划与完成度可观测。`reason="user_stopped"` 且 `resumable:true` 表示用户主动停止、可基于断点继续（§3.12.8）。**`state(complete\|error)` 先于 `done`** |

- **请求体 `resume`（`ChatRequest.resume`，默认 `false`）**：`true` 时显式恢复最近可继续的 FSM
  run（同 `run_id`，revision 递增）；若既无 resumable FSM 快照、也无可恢复的遗留
  `TurnCheckpoint`，返回 **HTTP 409**。普通新消息（`resume=false`）在 hydrate 前 abandon
  更早的可继续 run。FSM 快照对历史/恢复**权威于** `TurnCheckpoint`：存在任意非 resumable
  FSM 行时不以 checkpoint 回退。
- **历史 `resumable.state`**：`GET …/messages` 在可继续时附带公开 `state` 视图（`public_state_view`）；
  仅遗留 checkpoint 可恢复时仍给 checkpoint 形 payload。
- **确认再签发**：恢复后的确认拿到**新的** `request_id`（ConfirmBus 侧 ephemeral），不得复用中断前的 id。

- **会话（session）与对话（conversation）是两个概念**：`session_id` 是执行窗口（busy 保护 + TTL），`conversation_id` 是记忆作用域（持久，跨窗口存活）。请求体带 `conversation_id` 即**恢复该对话**——服务端优先复用其活跃会话，会话已过期则开新窗口但记忆延续。客户端只需持久化 `conversation_id`（前端存 `localStorage`）。
- 帧格式：`event: <name>\ndata: <json>\n\n`；文本含换行时 JSON 转义，天然安全。
- **心跳**：两次引擎事件之间可能长时间静默（例如逐份研报做摘要，单次可达 20–45s）。生成器每 `HEARTBEAT_S`（默认 15s）下发一个 SSE 注释帧（`: keep-alive`），既不污染事件流，又让字节持续流动，避免中间代理攒帧或按读超时截断连接。
- **心跳不能替代进展事件（重要）**：注释帧按 SSE 规范会被客户端**忽略**（`readEventStream` 只对含 `event:`+`data:` 的帧回调），而 `ChatPanel` 的空闲看门狗（`STREAM_IDLE_TIMEOUT_MS = 90_000`）只在**收到真实事件**时重置。因此"心跳保活"与"看门狗判活"是两回事：一个静默超过 90s、只发心跳的工具，连接不会断，但界面会在 90s 时主动 `abort()` 并报"响应流长时间无数据"。**长任务工具必须上报 `tool_progress` 事件**（`needs_progress=True`，由 loop 注入回调），否则会被看门狗误杀——2026-09 的 F8-3（横截面因子回测）即因面板取数静默 97s 而被掐断，其实工具当时仍在正常推进。相关阈值与真实事件语义见 `frontend/src/components/ChatPanel.tsx`（`armWatchdog`）与 `src/finharness/server/sse.py`。
- **终止保证**：`done` 帧在引擎落库之前下发（引擎先发 `done` 再 `_persist_turn`），因此答案一旦产生就一定送达；随后附着的轮次元数据若失败只记日志，不中断流。若引擎异常或未下发终止事件即退出，传输层会补发 `error` + `done`，绝不静默关流——否则浏览器无法区分"还在跑"与"已断开"，界面会永久停在"运行中"，只能刷新才看到结果。
- **反缓冲响应头**：`Cache-Control: no-cache, no-transform`、`X-Accel-Buffering: no`、`Connection: keep-alive`，确保逐帧即时到达浏览器。
- 方法选择：**POST 而非 EventSource(GET)**——EventSource 不支持请求体与自定义头，长消息受限；React 前端用 `fetch + ReadableStream` 消费同一 SSE 帧（解析器位于 `frontend/src/api/client.ts`）。
- **客户端收尾契约**：连接正常关闭 **不等于** 本轮完成。解析器显式跟踪是否收到 `done`/`error`，未见即抛错，由 UI 收敛为失败；`ChatPanel` 在 `finally` 中兜底关闭仍为"运行中"的 trace（传输失败、流被截断、空闲看门狗超时都会走到这里），并在组件卸载时 `abort()` 流，避免旧流事件写进已卸载实例。
- 幂等与异常：SSE 连接中断 → 服务端取消本轮 `AgentLoop` task（取消 `asyncio.gather`）。**取消路径同样落库**：`_run_once` 用 `try/except BaseException` 兜住 `CancelledError`（它继承自 `BaseException`，不会被引擎内的 `except Exception` 捕获），先同步调用 `_persist_turn()` 与 `_save_checkpoint("stopped", "interrupted")` 再重新抛出——否则用户提问与本轮全部中间成果会静默消失，客户端重连后只能看到上一轮。会话空闲超 TTL 由 `SessionRegistry` 淘汰；客户端重连发新请求即可续上。
- **停止信号的生命周期**：信号挂在 `ServerSession.stop_signal` 上（请求开始时新建、`finally` 中清空），因此停止端点能在 `AgentLoop` 之外够到它，而不会把上一次请求的停止状态泄漏给下一次。

**3.12.8 用户主动停止与断点恢复（v1.2 新增）**

一次生成可能跑很久（多轮取数、子代理扇出、报告终审），用户需要能随时喊停，**且不能因此丢掉已经取到的数据与形成的结论**。此前只存在"连接被掐断"这一条路径，而它既不落库（见上节）、也无法与网络故障区分。

- **两条通道，软硬互补**：① 软停止——`POST /v1/chat/stop` 置位协作式信号，引擎在下一个等待点收尾，正常下发 `answer`（部分发现）+ `done(reason="user_stopped", resumable=true)`；② 硬兜底——前端等待宽限期（`STOP_GRACE_MS`，8s）后仍未见终止帧，就用 `AbortController` 断开连接。断开路径由上面的取消兜底负责落库与写断点，因此兜底不丢成果，只是少了那份"部分答案"事件的收尾叙事。
- **协作式检查点**（`AgentLoop._stopped()`）：每个流式 chunk、每轮边界、工具 `gather` 返回之后各查一次。**工具返回后那一次最关键**——用户在耗时调用期间按下的停止，会保住这次调用已经取得的成果，而不是把它连同整轮一起丢弃。
- **停止不是失败**：不发 `error` 事件，trace 状态用 `stopped`（中性灰）而非 `error`（红），文案为"已停止/可继续研究"。把它渲染成错误会让用户以为系统出了问题。
- **confirm 必须同步解除**：引擎若正停在 `ask_user`/写确认的 `Future` 上，仅置位信号不会被观察到（要等 `confirm_ttl_s`，默认 120s），因此停止端点同时调用 `ConfirmBus.cancel_session()`。
- **子代理共享同一信号**：`Coordinator` 通过取值器把主循环的信号传给每个子 `AgentLoop`，因此报告终审/并行研究期间按停止也能及时生效；停止在子代理处同样以 `_stop_turn` 收尾。
- **轮次级断点**（`turn_checkpoints` 表，§3.6.9）：每轮收尾覆盖写一行，`status ∈ running|stopped|completed`，携带 `plan_json`（研究计划）、`partial_answer`、`rounds`、`persisted_seq`。计划是唯一无法从消息记录重建的执行态——它只活在 `ResearchContext` 里，进程重启即失——因此恢复的核心就是把它装回去。
- **恢复语义**：新一轮开始加载记忆时，若最新断点可继续（`status=stopped`）则把计划装回 `ctx` 并**消费掉该断点**（避免运行途中界面仍显示"可继续"）。模型于是看到完整历史 + 原有计划与各步状态，接着做而不是从头重来，也不会重复调用已标记 `done` 的步骤。已完成（`completed`）的断点不参与恢复，其计划只是上一轮的遗物。
- **审计与日志**：停止写 `action=generation_stopped` 审计行（此前文档 §8 承诺的 `aborted` 从未实现，这条覆盖了用户主动停止这一真实路径）；断流日志区分 `chat_stream_stopped`（用户停止）与 `chat_stream_disconnected`（传输掐断），否则"停止功能是否正常"无从判断。
- **前端**：生成中提交按钮替换为"停止"（中性灰，与"发送"的 accent 区分）；`done` 的 `user_stopped` 收敛为 `stopped` 态；刷新后由 `resumable` 渲染"继续研究"入口；切换对话时的静默 `abort()` 改为先 fire-and-forget 调用停止端点，使切走也不再白费这一轮。

**3.12.4 ConfirmBus（交互请求往返）**

- PermissionGate 的确认回调在服务端替换为 `ConfirmBus.request()`：① 向当前 SSE 通道推 `interactive_request`（`kind="confirm"`，确认选项随 payload 下发）；② `await asyncio.Future`，TTL=`settings.server.confirm_ttl_s`（默认 120）；③ 客户端 `POST /v1/chat/respond {request_id, response}` 填入结果（写工具 `y` / `y_session` / `n`；网络外发 `y` / `y_remember` / `n`）→ 引擎按 CLI 同路径回填 tool_result（批准执行 / 拒绝回填"用户拒绝"）；④ 超时未决 → 按拒绝处理。`ask_user` 提问走同一通道（`kind="question"`），payload 额外携带 `multi_select` 供前端决定单选/多选；多选答案由前端以「；」连接为单个 `response` 提交，服务端契约不变。
- 确认只在部署级 `permission.default_mode=auto` 时跳过（见 3.12.3 修订说明）；请求体无法按请求升权。
- 写工具首次确认时可选择"始终允许此类操作（本会话内）"（应答 `y_session`），之后**本会话内**的写类调用免问；该授权由 `loop_factory` 按会话持有，新建会话/会话过期重建即失效（docs 03.7.1）。网络外发（`web_search`、研报 `with_text`）首次确认，`y_remember` 后在本**对话**内免问——两者生存期不同，前者是会话级、后者是对话级。
- 会话断开但 confirm 未决：Future 取消，按拒绝收尾并审计。

**3.12.5 路由清单（薄控制器，全部经 SessionRegistry + AgentLoop）**

| 方法与路径 | 用途 |
|---|---|
| `POST /v1/chat/stream` | 发起一轮问答（SSE 流式返回，主接口）。body 可带 `conversation_id` 以恢复该对话 |
| `POST /v1/chat/respond` | 应答中途交互请求（write 确认 / `ask_user`），体为 `{request_id, response}` |
| `POST /v1/chat/stop` | **请求停止当前在飞的生成**（`{session_id?, conversation_id?}`，至少给一个）。协作式：置位该会话的停止信号并解除挂起的 confirm 等待，引擎在下一个等待点收尾；返回 `{stopping: bool, conversation_id}`。幂等（已结束/未在运行返回 `stopping:false`），归属不符按 404（不泄露存在性）。详见 §3.12.8 |
| `GET /v1/conversations` | 列出已持久化的对话（新建时间/最近活跃），供前端选择器 |
| `GET /v1/conversations/{id}/messages` | 回放该对话的可读历史（仅 user 与终答，不含工具帧），供恢复视图；响应另含 `resumable`（上一轮被停止时给出断点，否则 `null`，见 §3.12.8） |
| `DELETE /v1/conversations/{id}` | 删除对话及其全部对话内记忆（原文/摘要/引用/结论/标的），并**连带清理该对话来源的情节记忆**（`ltm_episodes.source_conversation_id` 匹配）与蒸馏台账；**语义记忆与用户偏好不受影响**（按 `(user_id, key)` 跨对话共享，见 §3.6.4「4.1」）；处理中返回 409 |
| `GET /v1/memory` | 已积累记忆的只读视图（偏好 + **跨对话情节** + **语义条目** + 对话列表 + 指定对话的结论）；情节/语义均支持 `kind` 过滤，`semantic_search` 字段如实报告本部署是否具备向量召回 |
| `PATCH /v1/memory/episodes/{ep_uid}` | 编辑一条跨对话情节（kind/subject/summary）；归属不符 404，改后与既有情节重复 409 |
| `DELETE /v1/memory/episodes/{ep_uid}` | 删除一条跨对话情节（遗忘权） |
| `PATCH /v1/memory/facts/{fa_uid}` | 编辑一条语义记忆（事实/概念/偏好）；用户改写偏好即"显式声明"，覆盖蒸馏口径；变更后自动重算向量 |
| `DELETE /v1/memory/facts/{fa_uid}` | 删除一条语义记忆，并同步清理向量库中的点 |
| `GET /v1/citations` | 溯源；`?conversation_id=` 按对话过滤（**优先**），`?session_id=` 兼容按会话；对话在进程内无注册表时回落到持久库（会话过期/服务重启后仍可读），返回含 `params` 取数入参 |
| `GET /v1/cache/stats` | 缓存命中统计（对应 /cache） |
| `GET /v1/tools` | 工具清单；带 `?session_id=` 时附带该会话的激活状态 |
| `GET /v1/artifacts` | 下载产出文件（`?path=`，限 output/ 与 data_cache/） |
| `GET /v1/health` | 存活探针（liveness） |
| `GET /` + `assets/` | Web 聊天页（React 构建产物，存在时挂载） |
| `GET/POST/PUT/DELETE /v1/config*` | 供应商配置（见 `config_api.py`：presets / CRUD / activate / probe） |
| `GET /v1/admin/status` | 管理员门控（`{is_admin}`）；`require_admin` 依赖，未登录 401、非管理员 403 |
| `GET /v1/admin/users?window=all\|24h\|7d\|30d` | 用户总览：三源合并（账号 + 对话数 + 用量），总累计与窗口列并列（`admin_api.py`，纯查看） |

**3.12.6 React Web 聊天页（frontend/，v1.1 新增）**

- 前端源代码位于仓库根目录 `frontend/`，技术栈为 React + TypeScript + Vite。
- 开发环境由 Vite 提供页面，并将 `/v1` 请求代理到 FastAPI；生产环境执行 `npm run build`，由 FastAPI 挂载 `frontend/dist`。
- React 组件负责消息流式区、工具状态行、计划面板、结论与 citations、新会话按钮以及后续的写工具确认弹窗。
- `frontend/src/api/` 负责 `fetch + ReadableStream` SSE 解析；SSE 事件名与后端协议保持一一对应。
- 前端不承载金融业务逻辑，所有研究能力仍经 FastAPI → AgentLoop → tools/data 执行。

**3.12.7 本模块验收点**

1. `curl`/浏览器走通一次复杂问答：plan → 并行取数 → 结论，事件顺序与 REPL 一致。
2. 触发 write_report：收到 `confirm_request`，点允许后生成 docx；点拒绝则模型收到"用户拒绝"并可继续对话。
3. 生成中点「停止」→ 收到 `done(reason=user_stopped, resumable=true)` 且**无 `error` 事件**；已获得的 citations 与部分结论仍在，刷新后本对话仍可出现"继续研究"；点继续后不重复取已完成步骤。（`tests/server/test_stop.py`、`tests/engine/test_user_stop.py`）
4. 断线（关页面/杀请求）→ 本轮提问与已有成果仍落库，断点记为 `stopped/interrupted`；审计出现 `generation_stopped`（用户主动停止路径）。重连同 session 可续问。
5. idle 超过 `session_ttl_s` 被回收；`/v1/health` 返回 200。
